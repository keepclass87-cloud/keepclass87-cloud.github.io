# TEPSUEV STUDIO — сайт-портфолио

Одностраничник моушен-студии: шестнадцать рекламных роликов, 2D и 3D.
Статика без сборщика — обычные HTML, CSS и JS. Публикуется на GitHub Pages.

---

## Запуск

```bash
python -m http.server 8000
```

Открыть http://localhost:8000

Двойной клик по `index.html` **не подойдёт**: скраб-ролики движок грузит
через `fetch` в Blob, а протокол `file://` такие запросы запрещает — вместо
видео останутся постеры, и проверять будет нечего.

---

## Из чего собрано

Страница стоит на движке **ScrollCraft** (`scrollcraft.js` + `scrollcraft.css`).
Движок не генерирует разметку: он читает с неё атрибуты `data-sc-*` и ведёт её
от одного значения прокрутки. Разметка написана руками.

**Движок не править.** Это механизм, общий для всех сборок. Всё своё —
в `site.css`, `site.js` и в разметке.

```
index.html          пятнадцать экранов, вся разметка
site.css            тема (шесть ролей цвета, два шрифта) и классы страницы
site.js             самодвижущиеся дорожки, ленивый запуск роликов, подсветка раздела
scrollcraft.css     движок, скопирован как есть
scrollcraft.js      движок, скопирован как есть
assets/video/       пережатые ролики: 15 плиток и фон первого экрана
assets/img/         постер-кадр к каждому ролику
assets/fonts/       Onest (OFL), с кириллицей, свой хостинг
```

## Грамматика страницы

**Монтажный лист** (`Rhythmic cutlist`): короткие сцены, жёсткие склейки,
ничего не залипает. Для студии, которая продаёт монтаж и тайминг, ритм
страницы и есть демонстрация ремесла.

Отсюда жёсткие правила, которые легко нарушить по неосторожности:

- ни один акт не длиннее ~1,4 высоты экрана;
- `pin`, `dwell`, `parallax`, `spotlight`, `magnet` **не применяются**;
- не больше двух `scrub`-актов — видео самое тяжёлое на странице
  (сейчас не используется ни одного);
- два одинаковых приёма подряд не ставятся.

Партитура, кривая чувства и пик описаны в [`BRIEF.md`](BRIEF.md). Он не
украшение: из него читается всё остальное, и проверка сверяется с ним.

## Три ловушки, на которых здесь уже один раз поскользнулись

**1. Сцене нельзя задавать `position`.** Движок делает `.sc-stage` липкой,
специфичность у правила такая же, а `site.css` подключён позже — своё
`position:relative` молча победит, и акт перестанет закрепляться. Движок
пишет об этом в консоль, но выглядит это как мелкое предупреждение.

**2. `data-sc-cue` и `data-sc-kinetic` работают только внутри акта.**
Без `data-sc-act` на секции движок не пишет `--sc-p`, и подпись навсегда
остаётся на нулевой непрозрачности. Выглядит как пустой экран.

**3. Фон первого экрана — обычная петля, не скраб.** Ролик My Element лежит
`<video class="hero__bg">` под затемнением и не привязан к прокрутке. Первый
экран вообще не акт: `data-sc-act` на нём нет, и ставить не нужно.

**4. Боковые ряды не зависят от прокрутки.** Они едут сами, CSS-анимацией:
`site.js` дублирует набор плиток и считает `--loop` (ширина первого набора
с просветом) и `--dur` (из скорости 70 px/с), а `@keyframes railrun` сдвигает
ленту ровно на `--loop`. В конце цикла копия стоит там же, где стоял
оригинал, поэтому возврата к нулю не видно.

Копии обязаны терять `id` и `data-work`: это якоря работ, и дубликаты
ломают переходы по ссылкам.

Сверхширокая работа (Око, 7680×1440) едет в той же дорожке. Соотношение у
неё 16:3, поэтому плитка ровно втрое шире обычной — так она встаёт той же
высоты, что соседние 16:9, и ничего не обрезается. Ширину обеих держит
одна переменная `--tile-w` на `.railrow__strip`: с двумя отдельными
`clamp()` высоты расходятся на узком экране.

## Видео

Мастера лежат вне репозитория, в `D:\Мои работы\лучшие`. В репозиторий едет
только пережатое.

| Роль | Параметры | Чем кодировать |
|---|---|---|
| Плитка (14 шт.) | 1280×720, GOP 48, CRF 27 | ffmpeg напрямую |
| Сверхширокая | 2560×480 + мобильный вариант | ffmpeg напрямую |
| Фон первого экрана | 1080p + мобильный вариант | ffmpeg напрямую |
| Сверхширокий | 2560 по ширине | ffmpeg напрямую |

Скраб-роликов на странице больше нет, поэтому плотный GOP не нужен нигде:
он требовался только перемотке колесом, которая отсчитывает от предыдущего
ключевого кадра. TV NE переехал в плитки и пережат обычным веб-кодеком —
9,5 МБ превратились в 1,7, а мобильный вариант на 3,9 МБ стал не нужен.

Звука нет ни в одном ролике — проверено. `-an` ничего не теряет.

## Проверка

У страницы с прокруткой нет одного состояния: каждое положение — отдельный
кадр, и поломки живут между теми двумя, на которые посмотрел.

```bash
node <скилл>/scripts/serve.mjs --root . --port 4500 &
node <скилл>/scripts/shoot.mjs --url http://localhost:4500 --out lab/shots
node <скилл>/scripts/shoot.mjs --url http://localhost:4500 --out lab/mobile  --width 390 --height 844
node <скилл>/scripts/shoot.mjs --url http://localhost:4500 --out lab/reduced --reduced-motion
```

Оснастка ловит мёртвую прокрутку, подписи, не дошедшие до полной
непрозрачности, и контраст, померенный на собранной странице. Дальше —
то, чего она не умеет: посмотреть `sheet.png` глазами и пройти табом
порядок фокуса.

Чего зелёный прогон **не** покрывает: настоящий телефон. Headless Chrome не
воспроизводит декодер видео, политику автозапуска и режим энергосбережения
iOS. Для живой проверки — `serve.mjs --lan` и открыть с телефона.

## Что осталось заполнить

На странице стоят **видимые** заглушки `— заполнить —`, красным. Пока они
есть, сайт не готов к публикации:

- описание студии — заглушка снята по просьбе заказчика, текст ставить в
  комментарий под заголовком в секции #about;
- город (всё остальное заполнено: мессенджеры и цены услуг);
- тип работы у Room Cold Brew.

Выдуманных цифр на сайте нет. Единственное число — 16 работ, и оно настоящее.

## Что убрано и почему это важно помнить

Монтажный лист, линейка под шапкой и блок «Услуги» сняты по решению
заказчика. Вместе с ними ушли `.hush` (пустой экран жил только ради
разворота панели) и пункт «Услуги» в шапке.

Последствие, о котором надо знать при любой следующей правке: **страница
короче бюджета грамматики** — 6,4 высоты экрана при диапазоне 8–14. Любое
новое сокращение делает её совсем короткой; если что-то убирается, лучше
одновременно что-то добавлять.
